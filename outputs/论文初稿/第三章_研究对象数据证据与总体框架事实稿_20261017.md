# 第三章 研究对象、数据证据与总体框架

2026-10-17，中文MEM论文事实稿。沿既有骨架第三章的问题与框架定位补充数据证据，不替换原骨架、方法稿、引文补注件或第六章。章节名称/编号及学校格式待作者审定。本文不报告新的实验成绩；【D01】等为内部证据定位，不是正式文献顺序编号。

## 3.1 研究对象与问题边界

本研究面向已有道路采集片段的离线复核优先级管理，以nuScenes v1.0-trainval为数据来源[1]。研究任务是将片段内的自车运动、交通参与者和地图信息组织为场景级表示，利用聚类与工程代理量产生可回溯的关键场景候选，供人工优先复盘。输出不直接等同于危险等级或事故概率，也不代替车辆的在线感知、预测与规划决策。【D01】【D05】

以scene而非单帧作为分析单元，可以在同一片段内保留事件的出现、持续及先后关系。对一个场景形成的特征向量、簇标签和排序位置，均以scene_name和scene_token回连原片段；帧级目标则还需要sample_token、annotation token与instance_token。多个时刻的目标证据不能只因位于同一场景便视为同一交互事件，场景分数也不能自动定位造成该分数的具体目标。【D02】【D04】

本章沿用“开发集”“评价集”“原始候选”“观测相关”“复核价值”等术语。开发回看用于修正规则，评价用于检验冻结方案；原始候选是运动或几何条件触发的结果，观测相关是另加轨迹条件的程序证据，二者都不是人工危险真值。成功让行或避障可以具有复核价值，交通密集、目标接近或离群本身则不构成已确认冲突。【D03】【D05】

## 3.2 数据组织与时间分辨率

nuScenes通过token关联场景、关键帧、传感器记录、自车位姿与目标标注。官方schema将sample定义为2Hz标注关键帧，sample_annotation关联sample而非某个单独相机的sample_data；同一实例可在多个标注时刻出现。sample_data具有自身时间戳和关键帧标识，回看时不能把相机帧号直接当作标注时刻。【D02】

本研究需要区分以下身份层级。它们用于追溯，不是不同层级的独立统计样本。

| 层级 | 主要身份 | 在本研究中的用途 |
| --- | --- | --- |
| 采集日志 | log_token | 约束开发/评价成员隔离 |
| 场景片段 | scene_name、scene_token | 场景表示、分组与复核排序 |
| 标注关键帧 | sample token、timestamp | 时间对齐与帧级事件统计 |
| 目标标注 | annotation token、instance_token | 具体时刻及同场景目标链追溯 |
| 传感器记录 | sample_data token、channel、timestamp | 关联回看材料与传感器时刻 |

官方schema说明实例身份不跨scene保持，因而不能以同一类车辆、相似外观或相近位置推定跨场景目标相同。更高帧率的前视回看可以帮助人工理解动作，但不会自动增加目标标注的时间分辨率，也不能将离散采样之间的运动视为已经连续测得。【D02】

本章对schema的引用采用项目已保存的官方upstream文档快照；它与本地nuscenes-devkit 1.2.0并非同一版本对象。字段是否可用、地图结构是否兼容，还应以本地数据能力清单和具体实现为准，而不能仅根据最新版网页推定本地运行能力。【D02】【D04】

## 3.3 自定义开发与评价划分

项目在本地trainval的850条场景内冻结了开发700条、评价150条，分别来自56与12个log，同一log不跨集合。该划分是项目自定义的日志隔离留出方案，不是nuScenes官方train/val拆分，也不是把官方剩余场景直接命名为本项目验证集。成员以冻结CSV和manifest中的身份、集合角色及文件摘要共同约束。【D03】

表3-1 冻结划分的地点组成

| 采集地点 | 开发场景 | 评价场景 |
| --- | ---: | ---: |
| boston-seaport | 384 | 83 |
| singapore-onenorth | 151 | 32 |
| singapore-queenstown | 95 | 20 |
| singapore-hollandvillage | 70 | 15 |
| 合计 | 700 | 150 |

来源为冻结划分manifest的location_counts，不涉及本轮查看评价片段或标签。四个地点在两侧均出现，日志隔离不能据此宣称地理区域、道路几何或交通模式完全独立；上表也不证明评价成员代表所有道路测试条件。【D03】

开发集用于特征讨论、规则修订、参数研究和案例纠错，评价侧不得参与这些选择。由于早期850条曾用于无监督探索，不能将这150条描述为项目历史上从未接触的盲测集。后续评价的隔离程度应以冻结后的过程约束说明，并披露历史接触限制；已反馈并用于改规则的开发案例不再用于独立准确率估计。【D03】【D05】

“训练集”容易被理解为已有监督标签用于训练预测模型，因此本稿统一采用“开发集”。这不改变原700/150成员或任何算法：它强调预处理、降维、聚类及评分参考量的拟合与选择只能依赖开发数据，不能在评价批次重新估计缩放、表示或排序参考量。【D05】

## 3.4 可获得证据与不能直接推断的语义

本地元数据、目标标注与静态地图为场景表示提供不同类型的证据，但它们并不包含同等完整的行为因果信息。位于walkway、附近有施工车辆、地图中有灯设施，分别是几何、类别或设施信息；将其升级为物理隔离、受阻改道或实时信号约束，都需要额外证据。【D02】

| 主题 | 已有证据及当前用途 | 不能直接转写成的结论 |
| --- | --- | --- |
| 交通参与者 | 类别、标注位置/尺寸、同场景目标链；参与帧级运动分析 | 某类别天然危险；未入选就证明目标不存在或标注完整 |
| 道路与人行道 | 静态lane、walkway、ped_crossing等几何关系 | walkway必然有护栏；目标在横道附近就已经穿行 |
| 信号与规则 | stop_line类型、traffic_light等设施代理 | 地图静态灯色是每帧实际相位；附近设施一定约束本车转向 |
| 可见性 | 六相机综合visibility标注与未标注状态 | CAM_FRONT专属遮挡率；传感器点数是视觉遮挡真值 |
| 施工与隔离设施 | 施工人员/车辆、锥桶和临时barrier的类别定义 | 出现即封路；barrier类别穷尽所有永久护栏 |

本地四份map expansion结构均记录为1.3；本章不据此认定所有场景的地图查询、目标匹配或道路占用均正确。静态地图能力与逐目标运行证据要分别审查，物理隔离的人工观察也不能自动改写成程序已识别的特征。【D02】

当前实现还有一个需明确披露的类别范围：名为vru_path_conflict等的路径候选只在human分支计算，自行车和摩托车走通用车辆分支并另有暴露/交互处理。因此，既有“VRU”字段名不代表已经统一覆盖所有易受伤害交通参与者；是否扩大范围或调整名称属于后续设计决定，本章不实施变更。【D04】【D08】

## 3.5 数据完整性、缺失与未知状态

文件完整、程序结构完整和语义证据完整是不同层次。已授权范围的150条评价与8条开发媒体恢复完成，审计对评价六路关键帧及前视关联非关键帧做了解码，其他相机关联非关键帧仅核对存在且非空。这说明该限定素材范围的恢复状态，不等于全库媒体验收、正式盲评包就绪或目标标注充分。【D07】

同样，数值为0不能一律解释为计算失败。它可能表示条件未触发、候选未通过后续规则，或在特定处理中被填充。判断应联合候选身份、发生时刻、有效比例、查询异常和来源版本，而不是只统计某列是否全0。没有足够证据时，也不能把0解释为已确认安全。【D05】【D08】

例如，在本次冻结开发证据中，0102和0151的观测最近中心距分别约9.84m和4.33m，但观测相关比例均为0；0053没有原始行人路径候选，距离30和时刻-1属于既有填值。这些例子只说明计算状态的区别，不是对当前类别范围、目标因果或真实安全性的整体验收。【D08】

当前固定29条轨迹侧写只保存完整车辆轨迹，没有完整human轨迹或人类候选台账。即使场景CSV中存在行人/VRU汇总量，也不能仅凭该侧写精确重放所有人类目标贡献。旧诊断中对0102保存的三帧逐目标汇总不等于完整未来坐标序列；0151的自行车隔离反馈更不能用于标注未定位的四帧人类候选。这是数据追溯能力缺口，不是程序已证明目标无关。【D08】

## 3.6 离线观测与在线应用的区别

现有开发方法会调用后续目标位置、自车观测路线及事件前后状态。这些信息可用于离线复盘，但在候选时刻未必可供在线系统取得。因此本研究的实现与诊断应标明使用观测未来，不把离线后处理称作实时预测能力，也不能仅凭离线结果宣称车辆在线决策已改善。【D04】【D05】

片段末端、目标链中断和采样间隙限制未来证据。当前部分新横向候选另保留未来未知状态，但不能将该能力推广到所有行人、纵向或避障字段；已有行人观测汇总缺少同等独立的完整未来状态。请求8s或10s窗口不等于实际观测已覆盖该时长，离散样本的最近距离也不等于连续车身扫掠安全证明。【D05】【D08】

此外，实际轨迹是车辆执行决策后的结果。成功让行或避障可能使后续路线分离，不能反过来抹去先前真实交互；反之，预测投影接近也不能自动证明自车需要让行。程序代理、观测结果和响应因果须分开保留，未来不足时不猜测视频外结局。【D05】【D06】

## 3.7 总体框架与验证接口

研究框架按数据身份、场景表示、无监督分组、候选排序和人工评价逐层组织。首先以冻结成员及目标身份确定数据范围；其次计算帧级几何/运动/地图证据并聚合事件；再按有序语义白名单进行开发集预处理、降维与聚类；最后结合稀有性、离群程度和工程代理量产生复核候选。独立专家评价用于检验冻结排序，而非倒过来参与评价集上的规则选择。【D04】【D05】【D09】

当前实现的52列聚类接口与完整结果表的129列不是同一概念，诊断身份、时刻和风险字段不能都算作聚类输入。全量v4开发表与后来v6.1/v7固定29条重放也属于不同证据阶段；不存在用最新候选代码名称即可自动继承旧700模型、簇号和TopK的关系。本章只说明框架与接口，不把各版本拼成一次已经完成的正式实验。【D04】【D06】

KMeans对照也应在相同成员、来源和明确披露的表示条件下解释。已有链路共用52列并不保证提取来源门控、支持度过滤、PCA/UMAP表示、搜索预算或排序量可比；本次链路审计仅定位这些缺口，没有产生新的KMeans实验或选择正式公平对照方案。【D10】

验证因此分为工程重放、开发语义核对和独立排序评价三层。摘要和结构核对回答是否按登记版本计算，开发反馈回答某些已见案例是否符合语境，独立评价才用于检验冻结排序的复核价值。现有统计工具和专家说明是准备材料，尚无真实盲评标签或正式有效性成绩；场景复核条数也不能直接换算为道路里程、工时或事故率收益。【D05】【D09】

## 3.8 本章小结

本章明确了scene级离线分析对象、日志隔离的自定义开发/评价划分，以及数据身份、静态地图、媒体和观测未来的证据边界。该框架为后续特征、聚类和评分章节提供可追溯的输入约束，但不预先证明特征语义、模型优越性或路测提效。正式特征/参数选择、样本外预测、专家校准和独立评价仍是待完成工作；本章不替代作者审定或正式实验冻结。

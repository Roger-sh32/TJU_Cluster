# 交互特征第二轮收紧设计

## 目标

基于第四批人工回看，收紧同车道 VRU、VRU 冲突、合流相关性和避障期间对向车特征。仅使用 nuScenes 地图、ego pose 与 `sample_annotation`，不引入摄像头目标检测模型。

## 数据边界

- nuScenes 画面中可见但没有 `sample_annotation` 的静止车辆不能由当前链路恢复。
- `scene-0042` 的两辆静止车在近场查询中没有有效车辆标注。本轮只消除其合流误判，并在存在有效标注时识别避障期间对向车。
- 地图查询失败时保留现有几何特征，但输出地图有效性标志；不把回退结果解释为严格车道归属。

## 规则设计

### 同车道 VRU

1. 使用 `layers_on_point(..., ['walkway'])` 判断 VRU 是否位于人行道；位于 walkway 时不得计入同车道。
2. 查询自车最近的 lane 或 lane connector，并以离散中心线建立局部车道走廊；VRU 必须落入自车当前车道走廊才算同车道。
3. 同向 VRU 需要沿车道方向具有正向速度，并形成持续事件；单帧速度噪声不输出同向事件。
4. 保留原始近场 VRU 暴露作为环境特征，但不得替代严格同车道特征。

### VRU 交互相关性

1. 现有 `vru_crossing_exposure_ratio` 继续表示潜在横穿暴露。
2. 为候选 VRU 读取后续 annotation 轨迹，并与 ego 已记录轨迹按时间同步。
3. 新增 `vru_observed_relevance_ratio`、事件数和同步最小距离。只有同步最小距离不超过 `6m` 的候选才进入严格 VRU 风险。
4. `obstacle_avoidance_vru_conflict_ratio` 改用观测相关 VRU，而不是瞬时匀速预测冲突。
5. 风险评分使用观测相关性和持续时间，远距离暴露不再使 `vru_risk` 饱和。

### 合流与对向交通

1. 合流候选必须具有明确正向速度；相对自车方向为对向的车辆不得进入合流候选。
2. 观测未来最小距离仅作为相关性复核，不能单独定义合流。
3. 新增 `oncoming_during_avoidance_ratio`：仅在已经识别出的静止障碍避让窗口内，统计前方对向来车暴露。
4. 对向事件独立于合流风险，避免 `scene-0042` 一类会车场景被错误归入合流。

## 验收场景

| 场景 | 验收要求 |
| --- | --- |
| `scene-0031` | walkway/车道几何应使同车道和同向 VRU 明显降低或归零；逆向行人不得算同向。 |
| `scene-0022` | 人行道 VRU 不得形成严格观测相关冲突，避障-VRU 复合事件应归零。 |
| `scene-0030` | 保持避障阳性、VRU 复合事件阴性。 |
| `scene-0042` | 合流暴露和观测相关性归零；不要求恢复无 annotation 的静止车辆。 |
| `scene-0008` | 远距离 VRU 可以保留暴露，但严格观测风险和综合风险不得继续饱和。 |

回归保护：`scene-0006` 的同车道同向行人、`scene-0011` 的避障后行人、`scene-0029` 的低风险红灯停车及 `scene-0047` 的真实合流不能被新规则破坏。

## 验证方法

- 所有几何与事件规则先在 `HDBSCAN/tests/` 添加失败测试，再写实现。
- 重跑前 50 场景调试表，不覆盖正式 850 场景文件。
- 检查输出无 NaN/Inf，并逐项核对五个验收场景和四个回归场景。
- 重新导出必要动图仅用于人工复核；50 场景 HDBSCAN 聚类结果不作为正式质量结论。

## 实施结果

2026-07-11 已按本设计完成前 50 场景调试重跑：

- `scene-0031` 的同车道、同向和严格观测相关 VRU 均归零。
- `scene-0022` 的人行道 VRU 不再形成严格冲突或避障-VRU 复合事件。
- `scene-0030` 保持避障阳性、VRU 复合事件阴性。
- `scene-0042` 的单帧伪合流通过朝向和 1 秒持续时间规则归零；未标注静止车仍属于数据边界。
- `scene-0008` 保留预测暴露，但同步最小距离为 `7.058m`，严格 VRU 相关性归零。
- `scene-0006`、`scene-0011`、`scene-0029` 和 `scene-0047` 的关键人工结论保持不变。

### 第五批反馈后的语义拆分

- `overtaking_exposure_ratio`：同向、侧方且纵向速度至少比自车快 `1m/s` 的持续超车暴露，不直接代表冲突。
- `merge_observed_relevance_ratio`：排除纯超车后，车辆与自车未来路径在同步时间内接近，表示路径汇合相关性。
- `merge_lane_entry_relevance_ratio`：相关车辆进一步实际进入当前自车 lane，是比路径汇合更严格的语义。
- `vru_observed_min_distance_time`：严格 VRU 候选达到同步最近距离的场景内时间，可结合停车、路口通过和转向阶段解释事件先后。

短时远距静止障碍不再单独触发避让。若目标持续不足一秒且距离超过 20 米，只有自车横移至少 4 米且最终航向变化不超过 0.10 弧度时，才视为具有足够强的避让证据。

### 事件归因扩展

- TTC 不再只输出场景最小值，同时记录产生该值的 annotation/instance、目标类别、场景时刻、净距离、横向位置、目标速度、相对速度和航向差。
- `stopped_lead_ratio` 表示目标在当前帧停止；`stationary_lead_obstacle_ratio` 表示该实例整段场景始终静止；`temporarily_stopped_lead_ratio` 表示该实例在场景其他时刻曾运动。
- `crossing_conflict_pre_stop_ratio` 与 `crossing_conflict_post_stop_ratio` 按首次持续停车时刻拆分横向冲突。
- `left_turn_cross_traffic_interaction_ratio` 表示左转过程中横向车流与自车路径形成交互，不要求停车和横向车辆在同一帧同时出现。
- 左转横向车流已经形成明确语义时，不再重复计入 merge 风险；信号灯下起始排队停车会衰减近距跟车风险。
